## 2. 資料來源的發現

### 2.1 ramirobentes（主要 play-by-play）

| 發現 | 類型 | 處理 |
|---|---|---|
| 沒有 team_id，只有球隊縮寫 | 事實 | 用 shotdetail join 取得（≥ 99% 一致才對應） |
| msg_type 99 是來源自己加的列 | 事實 | 排除並計數；在來源的回合欄位裡，它負責結束每節最後一個回合 |
| 換人列的陣容是「換人後」 | 事實 | **定義已改成和來源一致**（每次換人開始新的 stint；推翻審查者原本的定義） |
| 不同事件共用 `number_event` | 事實 | 依 NBA event_num 排序並回報 |
| player1/2/3 的角色隨年代改變；2025-26 抄截、蓋火鍋另有獨立列 | 事實 | 寫進 `possession_rules.md`；計算時避免重複 |
| `locX/locY` 是 0–100 的百分比座標 | 事實 | 不用；投籃座標全部用 shufinskiy |
| 8 個犯規事件被重複成兩列（7 季） | 事實 | 兩列只在來源推算的罰球欄位不同，官方 PBP 每個事件都只出現一次 → 依規則刪除一列；7 季因此全部載入 |
| 2024-25 季後賽少了 `0042400231` | 事實 | 列入 `known_gaps`，比賽列由 box score 建立（`pbp_missing`） |
| 2025-26 `0022500029`：一次罰球記為命中，但比分沒有變 | 事實 | 列入 `known_gaps`（`source_score_conflict`） |

| 檢查 | 結果 |

### 3.1 Box score 分鐘數

- **推論（已知來源現象，不再調查）**：2004-05 → 2006-07 的 box 分鐘被調整成每隊加總剛好等於比賽長度，所以個別球員會差 ±1–2 分鐘。
- **事實**：差異 > 5 分鐘的球員-比賽：
  - 2005-06 有 110 筆，**全部**是 box score 比較可能錯。BigDataBall 算出的分鐘數和我們的 PBP 在 110 / 110 筆都相差不到 1 分鐘；那些比賽的球隊 box 總分鐘中位數少了 90 分鐘。
  - 2006-07 有 243 筆，其中 237 筆 box 比較可能錯。
  - 1996-97 有 16 筆，原因不一。
  - 以上分類都是推論。

### 3.2 BigDataBall（7 季）

| 季 | 最終比分不同 | 陣容一致率 | 分歧段落：可判斷 / 總數 | ramirobentes 對 : BigDataBall 對 |

| 2010-11 | 0 | 98.39% | 4 / 15 | 4 : 0 |

- **推論**：兩邊的陣容分歧時，用 box score 分鐘數和官方換人紀錄判斷，**絕大多數是 ramirobentes 對**，BigDataBall 只在 2005-06 有 6 段是對的。
- 「從換人開始」和「從節開始」兩類分歧都是如此。

## 4. 投籃資料品質

- **事實（你確認的座標系統）**：在 NBA shot chart 座標中，(0,0) 是籃框位置。
- **事實**：每一季 (0,0) 出手中有 96–100% 是上籃、灌籃或補籃，距離 > 0 的有 0 筆。所以 (0,0) 代表「籃下出手、位置不精確」，不是缺漏。
- 旗標存在獨立的表 `core.shot_quality_flags`，重新載入不會消失：
  - `rim_location_imprecise`：703,971 筆。適用於 1996-97 → 2009-10，那幾季有 22–36% 的出手都在 (0,0)。
  - `rim_location_suspect`：3,191 筆。在 (0,0) 卻是跳投或三分球；1996-97 最多，有 665 次跳投、448 次三分。
  - `early_season_location_suspect`：729,649 筆。1996-97 → 1999-00，依 Sports Reference 的提醒標記。

## 5. 回合規則的準備研究

都用**參考回合**計算（ramirobentes 的回合欄位、pbpstats），不是我們自己的回合邏輯。2004-05 的數字：

| 情況 | 數字 |
|---|---|
| 回合總數 | ramirobentes 227,649；pbpstats 226,220（差 +1,429） |
| 節末殘局排除數（≤ 2 / 3 / 5 秒且 0 分） | 1,455 / 1,893 / 2,474 |
| 罰球之間換人 | 25.5% 的多罰球 |
| 跨越多段 stint 的回合 | 10.1% |
| 技術犯規罰球由防守方投 | 287 次 |
| 垃圾時間（CTG 官方定義，已對照確認） | 1.75% 的回合；我們自己算的先發人數和來源欄位 100% 一致 |

### 5.0 回合數基準（逐場逐隊，所有賽季）

| 比較 | 到 2015-16 | 2016-17 以後 |
|---|---|---|
| ramirobentes（去掉 ≤ 2 秒且 0 分）vs pbpstats，例行賽：差 0 / 差 ≤ 1 | 98.8% / 100.0% | 78.3% / 97.7% |
| ramirobentes（全部）vs NBA 官方 POSS，例行賽：差 0 / 差 ≤ 1 | 63.5% / 93.3% | 88.8% / 98.8% |

- **事實**：2016-17 前後明顯分界，季後賽的模式也一樣。整體來說：
  - 對 pbpstats：50 個賽季檔案中，差 0 的佔 91.5%。
  - 對 NBA 官方：60 個賽季檔案中，差 0 的佔 72.0%。
- **推論**：ramirobentes 的回合計算在 2016-17 前後改變，之後比較接近 NBA 官方。2015-16 以前扣掉節末殘局後，幾乎完全等於 pbpstats。這會影響之後拿哪一個當對照組。
- **有證據支持的推論：分界來自 ramirobentes 的處理流程。**
  - 依據：ramirobentes 的 README 說明，2016-17 起換了新的處理流程，但 2020-21 季後賽改用舊流程。
  - 2020-21 季後賽和 pbpstats 完全一致的佔 94.1%，和 NBA 官方一致的佔 58.8%，模式和 2015-16 以前一樣；同季例行賽則是 78.2% / 91.3%，和 2016-17 以後一樣。
  - 所以回合程式的主要對照組是 pbpstats（2000-01 → 2024-25）；ramirobentes 的回合欄位跨年代不一致，只作參考。
- 逐場結果存在 `reference.possession_count_benchmark` 和 `reference.possession_count_benchmark_official`。

### 5.1 得分存放設計的檢查

設計是：possessions 只留進攻方得分，不含技術犯規罰球；球隊總分從事件表加總。檢查 2004-05 和 2024-25 中，所有「得分隊伍 ≠ 當時進攻方」的得分事件：

| 類型 | 2004-05 | 2024-25 | 說明 |
|---|---|---|---|
| 技術犯規罰球 | 237 | 223 | 設計已經處理 |
| and-1 加罰 | 3,915 | 4,231 | **推論**：參考回合把回合結束點放在投進那一球，所以加罰落到下一個回合；照我們的規則（and-1 在罰球後才結束），它們屬於投籃方的回合 |
| 節邊界的罰球 | 1 | 2 | 犯規在節末，罰球被參考回合歸到下一個回合 |
| 其他 | 1 | 1 | 已逐一列出 |

依計畫的規則，因為不是全部都是技術犯規罰球，所以**沒有宣告設計成立**，標記 [待確認]。

### 5.2 開發策略：先複製，再偏離

- `rules.yaml` 有兩組設定檔。
- `pbpstats_compat`：回合中換人採用 pbpstats 的混合做法，回合數算給回合結束時的陣容，罰球得分算給犯規當下的陣容。
- `custom`：你的調整；回合中換人的規則維持 open。
- 回合程式完成後，先用 `pbpstats_compat` 逐場對照 pbpstats；不一致的地方逐一調查，不為了對上數字而修改邏輯。
