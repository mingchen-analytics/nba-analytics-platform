# Documentation map

Start with the [project README](../README.md). This folder has three kinds of documents.

## Design documents (English): read these to understand the project

| Document | What it is |
|---|---|
| [possession_rules.md](possession_rules.md) | The possession rules with worked examples and counts from real data; which rules are decided, proposed or open |
| [decisions.md](decisions.md) | Dated log of every design decision, with the reasons and the evidence; entries marked **[待確認]** are my conservative choices waiting for confirmation |
| [data_model.md](data_model.md) | Keys, relationships and which validation check protects each one; why the large tables carry no foreign keys |
| [data_dictionary.md](data_dictionary.md) | Tables and columns, source quirks, era differences |
| [dashboard_spec.md](dashboard_spec.md) | The three dashboard layers and what each page needs |
| [possession_implementation_guide.md](possession_implementation_guide.md) | The order in which the possession code was built and the checks on each step |
| [nba_api_endpoint_inventory.md](nba_api_endpoint_inventory.md) | Which NBA.com endpoints were probed and what they return |

## Validation reports ([validation/](validation/))

Generated by the pipeline; numbers and IDs only. Good starting points:

- [season_report.md](validation/season_report.md): one row per season, every check
- [possession_summary.md](validation/possession_summary.md): our possessions vs pbpstats, all seasons
- [possession_benchmark.md](validation/possession_benchmark.md): the source's own possession columns vs pbpstats and NBA's official counts
- [box_vs_pbp.md](validation/box_vs_pbp.md): official box score vs the same statistics counted from my events
- [bigdataball_crosscheck.md](validation/bigdataball_crosscheck.md): lineups and scores against a second source
- [duplicate_verification.md](validation/duplicate_verification.md): how duplicated source events were verified before being dropped
- `possession_check_{year}_{type}.md`: one report per season

## Working notes (mostly in Chinese)

The day-by-day record of how the project was built: plans, overnight batch reports, a progress log with real
timestamps, a research summary and the questions waiting for a decision. They are kept because they show the
process, and they are not needed to use the project.
